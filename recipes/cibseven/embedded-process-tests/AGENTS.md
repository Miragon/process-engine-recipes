# AGENTS.md

Open this folder as the project. Build with `./mvnw -B verify`. It runs the four process test classes, writes the coverage report to `target/process-test-coverage/` and the JGiven report to `target/jgiven-reports/html/`. Versions live in `pom.xml`.

The recipe shows two styles of process test for the same process, each once with plain element ids and once with the bpmn-to-code Process API:

| Package under `src/test/java/.../adapter/process/` | Style |
| --- | --- |
| `plain` | CIB seven Assert, `@SpringBootTest` |
| `bdd` | JGiven, in-memory engine without Spring |

Each package holds `BikeLeasingProcessTestV1` (plain element ids) and `BikeLeasingProcessTestV2` (ids and paths from the bpmn-to-code Process API); that is their only difference. Surefire picks them up through the `**/*TestV*.java` include in `pom.xml`, next to `**/*Test.java` for the unit tests. Keep the four classes on the same three scenarios, so they stay comparable. A new path gets a test in all four. Delegates and the process adapter always run for real; only the inbound use cases are mocked. Never complete a job or a service task by hand: run its job, so the delegate executes.

`bike-leasing.bpmn` is the bike order model from chapter 5.2 of the CIB seven developer training, plus `asyncBefore` on the service tasks. Keep its element ids. The Process API in `src/main/java/io/miragon/miravelo/leasing/adapter/process/` is generated by the bpmn-to-code Maven plugin on every build and committed; never edit it by hand.

The layering follows process-engine-blueprints: inbound use cases in `application/port/inbound`, the process port `LeasingProcess` in `application/port/outbound`, delegates in `adapter/inbound/cibseven`, the process adapter in `adapter/outbound/cibseven`. The services are logging stubs. Do not add REST, persistence or a frontend.

Every delegate, the process adapter and every service has a unit test without an engine. Keep them short: given, when and then separated by one blank line, no comments, Mockito mocks as fields and the class under test named `underTest`.
