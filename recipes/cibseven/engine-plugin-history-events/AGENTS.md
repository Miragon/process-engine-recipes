# AGENTS.md

Open this folder as the project. Build with `./mvnw -B verify`; it needs no broker and no containers. Versions live in `pom.xml`.

The recipe shows one engine plugin: `ProcessEventsPlugin` registers `ProcessEventsHistoryHandler` as a custom history event handler in `preInit`. The handler turns history events into `ProcessEvent`s and publishes each one after the engine transaction commits. Keep the default database history handler on; Cockpit depends on it.

The layering follows process-engine-blueprints:

| Package under `src/main/java/.../leasing/` | Role |
| --- | --- |
| `adapter/inbound/cibseven/history` | Plugin and history event handler, the only code that imports engine `impl` classes |
| `adapter/inbound/cibseven` | `OrderBikeDelegate` for the service task |
| `application/domain` | `ProcessEvent` |
| `application/port/inbound`, `application/service` | `PublishProcessEventUseCase` and `OrderBikeUseCase` with their services |
| `application/port/outbound` | `EventBus` |
| `adapter/outbound/eventbus` | `SpringCloudStreamEventBus`, sends through Spring Cloud Stream's `StreamBridge` |

The handler is created by the plugin and is not a Spring bean. The CIB seven Spring Boot starter registers a single `HistoryEventHandler` bean on its own; a bean that the plugin also registers receives every event twice.

`ProcessEventsProcessTest` runs the embedded engine with Spring Cloud Stream's test binder (`TestChannelBinderConfiguration`) and reads the destination `process-events` through `OutputDestination`. Keep its three scenarios: all process events in order, the default history still written, nothing published when the transaction rolls back. `Task_OrderBike` has no `asyncBefore`, so a failing delegate rolls back the completion of `Task_ApproveApplication`; that is what the rollback scenario relies on.

The Process API in `src/main/java/.../adapter/process/` is generated by the bpmn-to-code Maven plugin on every build and committed; never edit it by hand. Edit `bike-leasing.bpmn` with the bpmn CLI and keep its element ids.

Every piece outside the handler has a unit test without an engine: given, when and then separated by one blank line, no comments, the class under test named `underTest`. Do not add REST controllers, persistence or a frontend. `stack/docker-compose.yml` runs Kafka and Kafka UI for manual runs only.
